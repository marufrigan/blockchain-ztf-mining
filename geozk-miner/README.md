# GeoZK-Miner

Research prototype for **GeoZK-Miner**, a blockchain and zero-knowledge proof framework for
privacy-preserving conflict-mineral provenance and reacquisition governance.

A mine proves that a mineral batch originates from an auditor-approved region without revealing
its coordinates. Ethereum-compatible smart contracts bind each proof to one batch, enforce an
ordered, role-gated lifecycle and resolve disputed batches through an on-chain decision rule.

## Components

| Path | Content |
|------|---------|
| `circuits/regionProof.circom` | Region-membership circuit: Poseidon commitment `C = H(x, y, r)`, 32-bit range checks, bounding-box membership, region hash `h = H(minX, maxX, minY, maxY)` (1687 R1CS constraints) |
| `circuits/compile-circuits.sh` | Compiles the circuit and runs the Groth16 setup (local Powers of Tau with two contributions and a beacon unless `powersOfTau28_hez_final_12.ptau` is supplied) |
| `contracts/StakeholderRegistry.sol` | Role registry (mine, logistics, smelter, manufacturer, auditor) on OpenZeppelin AccessControl |
| `contracts/RegionProofVerifier.sol` | snarkjs-generated Groth16 verifier (BN254, EIP-197 precompile) |
| `contracts/GeoZKMiner.sol` | Core contract: region approval/revocation, commitment-bound batch creation, proof registration, forward-only lifecycle with custody, reacquisition request and rule-based resolution |
| `test/` | 28 functional and adversarial tests (real Groth16 proofs for verification, lifecycle and reacquisition) |
| `scripts/runEvaluation.js` | End-to-end evaluation on a local node (experiments E1 to E7) |
| `results/` | Raw outputs of the evaluation runs (E1 to E8) |
| `figures/` | Scripts that draw the result figures and event-log panels from `results/` |

## Decision rule for reacquisition

`resolveReacquisition(requestId, complianceValid)` derives `originValid` on-chain
(stored ZKP result and current region approval) and sets the decision to

* `REJECTED` if `originValid` is false,
* `APPROVED` (batch `REACQUIRED`) if `originValid` is true and `complianceValid` is false,
* `AUDIT_REQUIRED` otherwise.

`complianceValid` is the auditor's attestation; a certificate-specific ZKP is future work.

## Setup

```bash
npm ci
npx hardhat compile        # set USE_LOCAL_SOLCJS=true and `npm i --no-save solc@0.8.23` to compile offline
npm test
```

The compiled circuit (`circuits/build/regionProof/`), proving key and verification key used for the
reported results are included. Running `npm run circuits:compile` performs a fresh setup and
regenerates `RegionProofVerifier.sol`, so proofs and gas values will differ slightly from `results/`.

## Reproducing the evaluation

```bash
npx hardhat node                      # terminal 1
N_BATCHES=500 npm run eval            # terminal 2, writes results/E1 ... E7
npx hardhat test > results/E8_test_suite.txt
npm run figures                       # charts (Python 3, matplotlib, numpy)
npm run figures:logs                  # event-log panels (XeLaTeX)
```

| File | Experiment |
|------|------------|
| `E1_deployment.json` | Deployment gas, bytecode size, fees |
| `E2_workflow_trace.json` | Receipts and decoded events of one complete batch workflow |
| `E3_operations.json` | Gas and latency of every operation over N independent batches |
| `E4_proof_timing.json` | Witness generation, proving and off-chain verification time |
| `E5_artifacts.json` | Circuit statistics and artefact sizes |
| `E6_load_automine.json` | Response-time percentiles and throughput for 1 to 128 concurrent clients |
| `E7_load_interval.json` | Inclusion latency of transaction bursts with 12 s blocks |
| `E8_test_suite.txt` | Test-suite output |

All values come from local Hardhat runs. They are not public-network measurements. The locally
generated trusted setup is suitable for research only; production use requires a public
multi-party ceremony.
